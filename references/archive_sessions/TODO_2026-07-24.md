# Tomorrow's Investigation: Root Cause of Remaining ~5% Error

## Critical Observation

Baseline `cityage.csv` ANs were **NOT** generated by `03_attribution.R` — that script only computes ANs for years ≥ 2010 (`projrange` starts at 2015, minus `perlen=5`). So `cityage.csv` comes from an **earlier script** (likely the original 2023 Lancet Planetary Health pipeline), using **different temperature data**.

## Hypotheses to Test (in order)

### 1. Temperature data mismatch (HIGH PRIORITY)
Our `obs_data` (ERA5, 1990-2019) may differ from the ERA5 data Masselot used to generate `cityage.csv`.
- **Check**: Read `02_prep_data.R` to see how `obs_data` was extracted
- **Check**: Compare a few days of our `obs_data` against Masselot's original ERA5 (if available in `references/2025-masselot-zenodo/`)
- **Fix**: If different, we need to locate the exact ERA5 file Masselot used

### 2. Point estimate vs simulation mean (MEDIUM PRIORITY)
Masselot's `allcoefs` includes the point estimate (`ptcoef`) as column 1, then 500 sims. The `impact_summarise` function uses `res == "est"` for the point estimate separately. Our code averages 500 sims only.
- **Check**: Does using `ptcoef` (first row of coefs.csv, with `sim == 0` or similar) produce exactly the baseline ANs?
- **Test**: Include `ptcoef` as an additional "sim" and compare

### 3. Death rate differences (MEDIUM PRIORITY)
Masselot merges death data by `year5` (5-year blocks) from Wittgenstein projections calibrated to Urban Audit. We use a constant baseline death rate from `city_results.csv`.
- **Check**: For the 2000-2014 period, do the projected death rates match the baseline exactly?
- **Test**: Compute AN using Masselot's `projdata` death values instead of constant `city_results.csv` death

### 4. `dlnm` package version / `bs()` behavior (LOW PRIORITY)
Different R/dlnm versions might produce slightly different B-spline basis matrices.
- **Check**: `sessionInfo()` in Masselot's original environment vs ours
- **Test**: Compare the basis matrix at MMT for a known temperature vector

## Quick Test Protocol

For a single city (e.g., AT001C):
1. Compute AN using exact point estimate coefficients only (no simulations)
2. Compute AN using ERA5 data only (no bias correction, no GCMs)
3. Compare city-level results to `cityage.csv` `excess_cold_est` / `excess_heat_est`
4. If still off → check the ERA5 data source
5. If exact match → the issue is in how we average over simulations
